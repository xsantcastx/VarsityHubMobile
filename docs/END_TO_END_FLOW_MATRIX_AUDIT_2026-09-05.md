## Method and evidence boundaries

Used `varsityhub-matrix-audit` and the user-provided architecture audit text. Read the current app/whole-app/coach matrices, September 1 audit, fix notes, architecture, and current source. Classified current defects separately from closed claims, policy choices, deferred features, stale files, and unverified runtime behavior.

Threat model first: authentication bypass, coach/org/founder escalation, cross-team and cross-user ID substitution, client-controlled role/payment fields, private/blocked content leakage, old-owner email capabilities, webhook/email replay, stale entitlement events, cache invalidation, and deep-link injection. Traced client → API client → auth/role middleware → domain helpers → PostgreSQL → asynchronous email/payment/cleanup side effects. Public share crawlers, device APIs, provider callbacks, and Redis are distinct trust boundaries.

Local PostgreSQL 14 audit databases were created separately for role, fan, ad, full-suite, and browser tests. They used the current Prisma schema. The org-name SQL helper/index migration omitted by `db push` was applied to the relevant disposable databases before final org-create reruns. This was **not** a historical migration/rollback rehearsal. Test email transport was suppressed and no real payment-provider transaction was initiated. Redis-dependent production behavior was not certified.

Evidence levels are kept distinct: source contracts; actual rendered React Native components with mocked network/native dependencies; real Express HTTP + local PostgreSQL; shared helper + PostgreSQL; actual Chromium + local API/DB; read-only provider/deployment metadata. A test filename containing “E2E” does not establish native-device/provider end-to-end coverage.

## Architecture, efficiency and notes triage

Keep the existing PostgreSQL/Redis modular monolith and shared client/query mechanisms. Useful existing efficiencies were verified: Feed bundles, RSVP batching, query scope before limits, single query client, program follow intent ledger with lossless fan-out, bounded story queries and capped collage layout.

The recurring defect is **different entry points applying different rules**: post versus story versus OG privacy; app versus email owner authorization; subscription deletion versus refund identity checks; checkout holds versus existing paid inventory; settings local state versus canonical auth state. Consolidating these specific policies gives more value than moving every screen into new directories during an audit.

Source-confirmed follow-ups needing additional runtime proof: process-local privacy caches can outlive another replica's Redis invalidation (30–60 seconds), including possible deployment overlap; cached game lists may outlive team privacy changes. Jest disables Redis, so its passing tests do not close these cases. Large files still concentrate logic: settings ~1,695 lines, profile ~2,380, organizations ~3,527, payments ~4,603. Module size is maintenance debt; no broad rewrite was attempted.
