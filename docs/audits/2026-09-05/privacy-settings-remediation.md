## Query cost and release limits

Removing unsafe authorization caches adds database reads. In a small local diagnostic, three warm old helpers used zero Prisma operations in approximately 0.46 ms; corrected helpers used three operations in approximately 1.64 ms. After privacy restrictions required follow/membership/owner checks, the same corrected group used eight operations in approximately 7.79 ms. Cached anonymous game reads used two bounded operations: approximately 7.38 ms before the restriction and 6.29 ms after. This is a diagnostic sample, not a production latency claim, representative workload benchmark or completed performance gate. The cached game path does not perform one authorization query per returned game.

No schema migration or data backfill is needed for privacy/settings/map changes. Server deployment carries the privacy gates; OTA/web delivery carries client behavior. Reverting the privacy server fixes reopens the reproduced disclosure paths, so forward repair is preferred. Actual camera/library upload, map SDK interactions, OS lifecycle, share presentation, cross-device sessions and provider transactions remain separate release gates. Neither these automated counts nor the persisted [production grant snapshot](shipped-notes.md) establish A+ readiness.
