# Session recovery remediation — September 5, 2026

The owner clarified the symptom as an iPhone remaining signed in, then requiring another login after about a week. This step started from clean `2ef9d977` and produced `8b8543e3`. The defects below reproduce against that baseline; the exact cause on the owner's physical iPhone remains unconfirmed.

The historical seven-day refresh lifetime was replaced by a rolling 365-day lifetime in `80fa6ded4` on August 4. This step does **not** extend that policy again. Current real HTTP/PostgreSQL tests confirm a login issues a 15-minute access token and a 365-day refresh token; a fixture aged eight days can refresh and receives another 365-day window. Existing tokens retain their stored expiration until successfully rotated. The eight-day test manipulates isolated fixture timestamps; it is not a week-long physical-device observation.
